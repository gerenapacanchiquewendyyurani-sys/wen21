¿Qué es un stakeholder?

Un stakeholder (también llamado parte interesada o grupo de interés) es cualquier persona, grupo u organización que puede influir, verse afectado o tener interés en las actividades, decisiones o resultados de un proyecto, empresa o institución.

El concepto fue desarrollado por el profesor R. Edward Freeman en 1984 y hoy es fundamental en la administración de empresas y la gestión de proyectos.

Características de un stakeholder:

• Tener interés en el éxito o fracaso del proyecto.

• Influir en la toma de decisiones.

• Aportar recursos (dinero, conocimiento, materiales o trabajo).

• Beneficiarse o verse perjudicado por los resultados.

• Tener diferentes niveles de poder, influencia e interés.

Clasificación 1: Según su relación con la organización

Tipo ¿Quiénes son? Ejemplos
Internos Pertenecen a la organización. Gerentes, empleados, socios, accionistas.
Externos No pertenecen a la organización, pero tienen relación con ella. Clientes, proveedores, gobierno, comunidad, bancos.

Clasificación 2: Según su poder e interés

Poder Interés ¿Cómo gestionarlo?
Alto Alto Gestionar de cerca y mantener comunicación constante.
Alto Bajo Mantener satisfechos.
Bajo Alto Mantener informados.

Clasificación 3: Según su importancia

Tipo Descripción Ejemplos
Primarios Son indispensables para el proyecto. Clientes, empleados, inversionistas.
Secundarios Influyen, pero no participan directamente. Comunidad, medios de comunicación, competidores.

Requerimientos Funcionales (RF)

Un requerimiento funcional (RF) indica lo que el sistema debe hacer. Es decir, son las funciones o acciones que tendrá el software.

RF = Función = ¿Qué hace el sistema?

RF-001

El sistema debe permitir registrar usuarios.

RF-002

El usuario podrá iniciar sesión con correo y contraseña.

RF-003

El sistema permitirá buscar libros por título.

RF-004

El usuario podrá prestar un libro.

RF-005

El administrador podrá eliminar usuarios.

Requerimientos No Funcionales (RNF)

Un requerimiento no funcional (RNF) indica cómo debe funcionar el sistema. No agrega nuevas funciones, sino que establece las condiciones de calidad del software.

RNF = Calidad = ¿Cómo debe funcionar el sistema?

RNF-001

El sistema debe cargar en menos de 2 segundos.

RNF-002

Las contraseñas deben almacenarse cifradas.

RNF-003

El sistema debe estar disponible el 99,9 % del tiempo.

RNF-004

Debe funcionar en computadores y celulares.

RNF-005

La interfaz debe ser fácil de usar.

RNF ¿Qué es? Ejemplo
Rendimiento Qué tan rápido funciona el sistema. Carga en menos de 3 segundos.
Seguridad Protege la información. Inicio de sesión con contraseña.
Usabilidad Fácil de usar. Botones claros y visibles.
Accesibilidad Puede ser usado por todos. Compatible con lectores de pantalla.
Disponibilidad Tiempo que el sistema está activo. Disponible el 99% del tiempo.
Escalabilidad Soporta más usuarios. Hasta 1000 usuarios.
Mantenibilidad Fácil de actualizar. Código organizado.
Portabilidad Funciona en varios dispositivos. Windows, Android e iOS.
Compatibilidad Compatible con otros sistemas. Chrome, Edge y Firefox.
Confiabilidad Funciona sin errores. No pierde información.
Restricciones tecnológicas Tecnologías obligatorias. HTML, CSS y JavaScript.
